# 通用解析能力 · 函数解析支持情况

> 维护范围：`sqlparserx-core` 中基于 `BaseSqlParser` 的**通用函数解析能力**，即不区分数据源的函数名提取能力。
> 实现思路参考：[基于Druid实现function函数解析](../../../../reference/sqlparserx核心解析层实现思路/基于Druid实现function函数解析.md)。
> 上层汇总入口见 [SQL解析能力&数据源支撑适配情况.md](../datasource/SQL解析能力&数据源支撑适配情况.md)。

## 一、实现目标

解析 SQL 中出现的函数名。函数名与血缘无关，属于**纯遍历提取**能力，因此直接使用 Druid 的 Visitor 访问者模式完成匹配。

```text
SQL
  → SqlSyntaxParser.parseStatements
  → 每个 SQLStatement.accept(SQLASTVisitorAdapter)
  → 命中 SQLMethodInvokeExpr / SQLAggregateExpr
  → Set<String> 函数名集合
```

## 二、Core 入口与实现位置

| 项目 | 内容 |
|---|---|
| Core 入口 | `ISqlParser.parseFunction(String sql)` |
| 默认实现 | `BaseSqlParser.parseFunction` |
| 返回类型 | `Set<String>`（已去重） |
| 解析对象 | SQLMethodInvokeExpr（普通函数、窗口函数）、SQLAggregateExpr（聚合函数） |

## 三、支持粒度与深度

| 能力项 | 支持情况 | 说明 |
|---|---|---|
| 普通函数名提取（`SQLMethodInvokeExpr`） | **已支持 ✅** | 如 `now()`、`concat(id, name)` |
| 聚合函数名提取（`SQLAggregateExpr`） | **已支持 ✅** | 如 `sum`、`count`、`avg` |
| 窗口函数提取（`xxx over xxx`） | **已支持 ✅** | 基于 `SQLMethodInvokeExpr` 识别 |
| 多语句 SQL 提取 | **已支持 ✅** | 遍历 `parseStatements` 得到的全部 Statement |
| 结果去重 | **已支持 ✅** | 使用 `HashSet` 去重 |
| 函数参数/表达式分析 | **不支持 ❌** | 只提取函数名，不返回参数与类型 |
| 函数分类（普通/聚合标签） | **不支持 ❌** | 统一放入同一集合，不区分类别 |
| 函数血缘 | **不支持 ❌** | 与血缘无关，不参与来源推导 |

## 四、典型示例

```java
Set<String> functions = sqlParser.parseFunction(sql);
```

| 输入 SQL（片段） | 输出函数名 |
|---|---|
| `select now() as current_time` | `now` |
| `select sum(o.id) as s, CONCAT(n.tt1, n2.tt2) as tmp` | `sum`, `concat` |
| `select row_number() over (partition by id order by ts) from t` | `row_number` |

## 五、能力边界

| 边界项 | 说明 |
|---|---|
| 仅函数名 | 输出为函数名的字符串集合，不含参数、返回值、调用位置 |
| 大小写 | 以 Druid AST 中 `getMethodName()` 原值返回，不做大小写归一 |
| 方言语义 | 不处理方法名映射（如不同方言同义函数名） |
| 无专项测试 | 当前由通用测试覆盖，尚未建立函数解析专项用例 |
