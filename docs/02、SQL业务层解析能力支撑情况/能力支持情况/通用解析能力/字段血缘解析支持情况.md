# 通用解析能力 · 字段血缘解析支持情况

> 维护范围：`sqlparserx-core` 中基于 `BaseSqlParser` / `ColumnLineageClient` 的**通用字段血缘解析能力**。
> 实现思路参考：[基于Druid实现字段血缘解析的核心思路](../../../../reference/sqlparserx核心解析层实现思路/基于Druid实现字段血缘解析的核心思路.md)。
> 上层汇总入口见 [SQL解析能力&数据源支撑适配情况.md](../datasource/SQL解析能力&数据源支撑适配情况.md)。

## 一、实现目标

从 SQL 中推导**来源表.来源字段 → 目标表.目标字段**的字段级血缘关系。

核心思路：把「来源 select 字段列表」与「目标字段列表」各自归一为 `(真实字段, 别名字段, 真实表名)` 的三元组集合，再按固定匹配规则生成血缘。字段血缘的输入是插入/建表类 SQL，纯查询 SQL 不产生血缘。

```text
SQLInsertStatement / SQLCreateTableStatement(AS SELECT)
  → ColumnLineageClient.parseColumnLineages
  → 目标字段列表 + 来源 select 字段列表
  → addColumnRelations 逐条匹配
  → ColumnLineageResult
```

## 二、Core 入口与实现位置

| 项目 | 内容 |
|---|---|
| Core 入口 | `ISqlParser.parseColumnLineages(sql, tableColumnsMap)` |
| 默认实现 | `BaseSqlParser.parseColumnLineages` → `ColumnLineageClient` |
| 返回类型 | `ColumnLineageResult`（`columnRelations` + `columnLineages`） |
| 适用语句 | `SQLInsertStatement`、`SQLCreateTableStatement`（AS SELECT） |
| 元数据输入 | `Map<String, List<Column>> tableColumnsMap`（表 → 字段列表） |

## 三、支持粒度与深度

### 3.1 字段场景

| 能力项 | 支持情况 | 说明 |
|---|---|---|
| `catalog.db.table.column` 字段识别 | **已支持 ✅** | 支持 Hive/Trino/StarRocks 等多 catalog 场景 |
| `db.table.column` 字段识别 | **已支持 ✅** | MySQL/PostgreSQL 等标准用法 |
| 字段表达式计算（`SQLBinaryOpExpr`） | **已支持 ✅** | 如 `t5.level + 1`，左右递归收集字段 |
| `*` / `xx.*` 展开 | **已支持 ✅** | 依据元数据 `tableColumnsMap` 读取字段；无元数据保留 `*` |
| `select *` / `select t1.*` 优化 | **已支持 ✅** | 子查询场景拷贝下层 selectColumns |
| `case when ... end` | **已支持 ✅** | 遍历 when 结构，识别字段 vs 字面量 |
| 带函数（有参数/无参数） | **已支持 ✅** | `sum(o.id)`、`concat(...)`、`now()`，多字段以 `,` 合并 |
| 嵌套聚合子查询（`SQLQueryExpr`） | **已支持 ✅** | 如 `(select count(*) from t)`，有元数据时展开 |
| `SQLCaseExpr`（`case()`） | **已支持 ✅** | 仅收集内部 `SQLMethodInvokeExpr` 结果 |
| `in (xxx, xx)`（`SQLInListExpr`） | **已支持 ✅** | 处理 expr 与 targetList，整型等字面量不作为字段 |

### 3.2 SQL 结构场景

| 能力项 | 支持情况 | 说明 |
|---|---|---|
| `with as` 血缘 | **已支持 ✅** | 含递归 CTE；主查询 `select t1.*` 匹配处理 |
| `insert into ... select` | **已支持 ✅** | 含 `insert into table select * from (select *)` 嵌套 |
| `insert overwrite ... select` | **已支持 ✅** | Hive 覆盖写场景 |
| `create table ... as select` | **已支持 ✅** | 列名随 select 走 |
| `with as` 搭配 insert（上/下两种写法） | **已支持 ✅** | Doris 等 with 在下场景 |
| `select union` 合并 | **已支持 ✅** | 真实字段/真实表名按 `,` 合并，别名保留第一组 |
| union all 字段数量不匹配 | **已支持 ✅** | 记录日志不报错，按两组匹配合并 |
| 子查询 + union 结构 | **已支持 ✅** | 复用子查询与 union 逻辑 |
| LATERAL VIEW 表 | **已支持 ✅** | 复用内部 tableSource 逻辑 |

### 3.3 识别深度

| 维度 | 深度 |
|---|---|
| 字段深度 | `catalog.db.table.column` ✅ |
| 表来源深度 | `catalog.db.table` ✅ |

## 四、核心匹配规则

1. 目标端字段列表：优先取 `insert into xxx(col...)` 指定列；否则取元数据表字段；再否则取来源 select 的别名字段。
2. 来源端字段列表：由主体 select 追溯汇总（子查询/CTE/union 归一）。
3. 逐条匹配：来源端「真实表名 → 来源表」「真实字段 → 来源字段」，目标端「别名字段 → 目标字段」。
4. 单列多字段（表格 `,` 合并）时，按 `,` 拆分为多条血缘记录。
5. 无来源表/来源字段为字面量时不产生血缘。

## 五、未支持 / 待明确场景

| 场景 | 状态 | 说明 |
|---|---|---|
| JOIN `on` 条件字段是否计入血缘 | **待明确 ❌** | 如 `table1.id = table2.id`，是否作为字段血缘一部分未定义 |
| `case when end` 作为独立属性 | **待明确 ❌** | 是否单独成列未定义 |
| 无元数据的 `SELECT *` 完整展开 | **不支持 ❌** | 缺少元数据时无法保证完整展开 |

## 六、元数据依赖

| 依赖项 | 说明 |
|---|---|
| `tableColumnsMap` | `*` 展开、目标字段补齐、子查询字段匹配均可能依赖表字段元数据 |
| 缺失影响 | 缺少元数据时 `*` 无法完整展开，可能保留 `*` 或退化为别名 |

## 七、异常与边界

| 边界项 | 说明 |
|---|---|
| 目标字段多于来源字段 | 抛出 `血缘解析异常，sql写法问题` 运行时异常 |
| union 字段数量不匹配 | 兼容处理，记录日志并按两组匹配，不报错 |
| 无匹配源表 | 过滤，不生成血缘记录 |
