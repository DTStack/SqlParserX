# 通用解析能力 · 表解析支持情况

> 维护范围：`sqlparserx-core` 中基于 `BaseSqlParser` / `ParseTablesClient` / `ParseCreateTableClient` 的**通用表解析能力**，包含真实表解析与 CREATE TABLE 结构解析。
> 实现思路参考：[基于Druid实现表解析实现](../../../../reference/sqlparserx核心解析层实现思路/基于Druid实现表解析实现.md)。
> 上层汇总入口见 [SQL解析能力&数据源支撑适配情况.md](../datasource/SQL解析能力&数据源支撑适配情况.md)。

## 一、实现目标

| 能力 | 目标 |
|---|---|
| 真实表解析 | 从任意受支持语句中解析出主表与全部真实表 |
| CREATE TABLE 解析 | 将建表语句解析为字段、键、分区、分桶、properties 等结构 |

真实表解析的 `select` 追溯逻辑与表血缘**共享**：普通 `select ... from`、字段中嵌套 `select max(id) from tables` 等，都复用表血缘的 `select` 追溯过程来定位真实表。区别在于真实表解析覆盖的 SQL 结构**多于**表血缘。

## 二、Core 入口与实现位置

| 项目 | 内容 |
|---|---|
| 真实表入口 | `ISqlParser.parseTables(String sql)` |
| 建表入口 | `ISqlParser.parseCreateTable(String sql)` |
| 默认实现 | `BaseSqlParser` → `ParseTablesClient` / `ParseCreateTableClient` |
| 结果类型 | `ParseTableResult`（`mainTable` + `allTables`）、`ParseCreateTableResult` |
| 共享服务 | `ParseSelectTableService`（from/with as 追溯，与表血缘同源） |

## 三、真实表解析支持粒度

### 3.1 语句类型

| 语句 | 支持情况 | 说明 |
|---|---|---|
| `SELECT` | **已支持 ✅** | 主体查询追溯真实表 |
| `INSERT` | **已支持 ✅** | 目标表 + 来源表；含 `with as`（上/下两种写法） |
| `UPDATE` | **已支持 ✅** | 提取目标表 |
| `DELETE` | **已支持 ✅** | 提取目标表 |
| `CREATE TABLE`（含 AS SELECT） | **已支持 ✅** | 目标表 + `select` 来源表 |
| `DROP TABLE` | **已支持 ✅** | 提取全部表 |
| `TRUNCATE TABLE` | **已支持 ✅** | 提取全部表 |
| `COMMENT ON TABLE/COLUMN` | **已支持 ✅** | 解析注释目标表 |
| `RENAME TABLE` | **方言增强 ✅** | MySQL 通过 `MysqlParseTablesClient` 识别 `MySqlRenameTableStatement` |

### 3.2 表来源结构（与表血缘共用）

| 结构 | 支持情况 |
|---|---|
| from 普通表（`SQLExprTableSource`） | **已支持 ✅** |
| join（`SQLJoinTableSource`） | **已支持 ✅** |
| 子查询（`SQLSubqueryTableSource`） | **已支持 ✅** |
| union / union 子查询（`SQLUnionQueryTableSource`） | **已支持 ✅** |
| LATERAL VIEW 表源（`SQLLateralViewTableSource`） | **已支持 ✅** |
| `with as` / 递归 CTE | **已支持 ✅** |

### 3.3 识别深度

| 维度 | 深度 |
|---|---|
| 表识别深度 | `catalog.db.table` ✅ |
| 结果拆分 | `mainTable` 为主表，`allTables` 含全部真实表 |

## 四、CREATE TABLE 解析支持粒度

| 项目 | 支持情况 | 说明 |
|---|---|---|
| `IF NOT EXISTS` | **已支持 ✅** | `isNotExists` |
| db / 表名 / 表注释 | **已支持 ✅** | `db`、`tableName`、`tableComment` |
| 字段列定义 | **已支持 ✅** | `tableElementList` |
| 分区字段（无类型） | **已支持 ✅** | `partitionedByList` |
| 表键（主键/唯一/聚合/重复） | **已支持 ✅** | `tableKey`，方言可覆盖 `dealTableKey` |
| 分桶（bucket num + 分布列） | **已支持 ✅** | `tableDistributedBuckets`，方言可覆盖 `dealDistributeByColumns` |
| 分区（范围/列表等） | **已支持 ✅** | `tablePartition`，含分区元素 |
| 表 properties | **已支持 ✅** | `properties` |
| 动态分区 | **方言增强 ✅** | Doris 开启 `isDynamicPartitionEnabled` 并识别 `dynamic_partition.enable` |

## 五、单独实现逻辑场景

| 场景 | 处理方式 | 说明 |
|---|---|---|
| `where ... in (子查询)` 中的表 | **表解析可识别 ✅** | 该类表属于间接影响/条件依赖，不作为直接表血缘，但表解析提供获取其真实表的能力 |

示例：

```sql
CREATE TABLE test_2a AS
SELECT cust_name, cust_contact
FROM Customers
WHERE cust_id IN (SELECT cust_id
                  FROM Orders
                  WHERE order_num IN (SELECT order_num
                                      FROM OrderItems
                                      WHERE prod_id = 'RGAN01'));
```

`Orders`、`OrderItems` 可被真实表解析识别。

## 六、能力边界

| 边界项 | 说明 |
|---|---|
| 真实表 vs 血缘 | 真实表解析覆盖语句多于表血缘；`where in` 子查询表计入表解析但不计入直接血缘 |
| 建表结构方言差异 | 键类型、分桶、分区由方言 Client 覆盖，Base 提供通用实现 |
| 未识别语句 | 未在 `ParseTablesClient.parseTables` 分发的语句类型不产生结果 |
| 元数据无关 | 表解析本身不依赖字段元数据 |
